# Contributing

## Requirements

- Node.js from `.nvmrc` (`lts/krypton`)
- npm

## Scripts

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite dev server on `127.0.0.1` |
| `npm run build` | Production build to `dist/` |
| `npm run preview` | Serves the production build |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint (flat config, `eslint-config-piecioshka`) |
| `npm run test` | Vitest unit tests |
| `npm run e2e` | Playwright tests on Chromium, WebKit and Firefox (headless) |
| `npm run format` | Prettier write |
| `npm run format:check` | Prettier check |
| `npm run fixtures` | Generates e2e fixture decks |
| `npm run ci` | Format check, lint, typecheck, test, build and e2e, same as in CI |

Install browsers once with `npx playwright install chromium webkit firefox`.

## Architecture

- `src/core` - framework-free logic (archive reading, relationships, export names). No DOM or React imports.
- `src/ui` - React components. They call `src/core` and never parse files themselves.

Exported image bytes must equal the archive entry bytes, so images are never decoded and re-encoded. The file is read only through `Blob.slice()` ranges, never loaded whole.

## Fixtures

E2E fixture decks live in `e2e/fixtures` and are generated by `npm run fixtures`.

## Tests

- Unit specs sit next to the code as `*.spec.ts`. UI specs (`src/ui/**/*.spec.tsx`) start with `// @vitest-environment jsdom`.
- E2E specs sit in `e2e/` and run against the production build served on port 4317.
- A `pre-push` hook (husky) runs `npm run ci`, the same steps as the CI workflow.

## Deploy

Every push to `main` runs `.github/workflows/pages.yml`, which builds with `BASE_PATH=/office-image-peek/` and publishes `dist/` to GitHub Pages.
